# Governance

Provenance is currently a maintainer-led v0.x proposal.

## Decision process

- Bug fixes, documentation clarifications, and implementation improvements are
  decided through pull request review.
- Changes to normative fields, relationship semantics, conformance, privacy, or
  versioning require a public issue before implementation.
- Decisions should prefer interoperability, implementability, and honest limits
  over adding fields for hypothetical use cases.
- Accepted normative changes must update the specification, schema, examples,
  implementation, and tests together.

The initial maintainer is [Raphael Salaja](https://github.com/raphaelsalaja).
The maintainer may appoint additional maintainers based on sustained,
constructive participation.

## Toward shared governance

Before a 1.0 release, the project intends to document:

- at least three independent implementations or adopting projects;
- a compatibility and deprecation policy informed by those adopters;
- a multi-maintainer approval process for normative changes;
- a neutral process for resolving disputed specification decisions.

Industry adoption cannot be declared by the repository itself. It emerges from
independent use, interoperable implementations, and shared stewardship.

## Maintainer responsibilities

Maintainers review contributions, publish releases, enforce the Code of Conduct,
protect confidential security reports, and disclose conflicts of interest that
could materially affect specification decisions.
